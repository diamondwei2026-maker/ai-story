## 二、路由设计

### 2.1 路由结构（嵌套路由）

```
/                           ProjectHubView（项目中心）
/project/:id                WorkflowView（工作流容器）
  /project/:id/idea         IdeaView
  /project/:id/setting      SettingView
  /project/:id/outline      OutlineView
  /project/:id/beats        BeatsView
  /project/:id/drafting     DraftingView
```

- 使用 createWebHistory() HTML5 History 模式
- 子路由通过 props 传递 projectId
- 阶段切换通过 router-view + Transition 实现动画过渡

### 2.2 阶段访问保护

无显式路由守卫。阶段保护通过以下机制实现：
- 各阶段视图在 onMounted 时从后端加载数据
- 阶段间导航通过 usePhaseWorkflow 的 handleConfirm 触发
- Stepper 点击通过 PHASE_TO_ROUTE 映射导航

## 三、状态管理

### 3.1 Store 架构

项目使用 **Pinia Setup Store** 模式，共 4 个 store：

#### useProjectStore

管理全局项目列表：
- projects: Project[] — 所有项目
- currentProject: Project — 当前选中项目
- 持久化到 localStorage
- 提供 loadProjects() / createProject() 等 CRUD 方法
- 项目状态枚举：IDEA | SETTING | OUTLINE | BEATS | DRAFTING | COMPLETED | ARCHIVED

#### useWorkflowStore

管理当前项目的工作流阶段状态：
- currentPhase: PhaseType — 当前活跃阶段
- phaseOrder: [IDEA, SETTING, OUTLINE, BEATS, DRAFTING]
- stepStatus: Record<PhaseType, StepStatus> — 每阶段状态
- 按项目隔离状态：loadForProject(projectId)
- 阶段状态枚举：PENDING | IN_PROGRESS | CONFIRMED | REJECTED
- 自动从后端同步状态（watch projectStore.projects）

#### useBeatStore

管理细纲 Beat 数据：
- beats: Beat[] — 带排序的 Beat 列表
- sortedBeats: computed 自动排序
- Beat 状态：PENDING | STALE | CONFIRMED
- 修改 Beat 时自动标记为 STALE
- Beat 包含：narrativeSummary, conflictDescription, pacingLabel, hookCausalChain, conflictIntensity 等

#### useChapterStore

管理章节数据（核心 Store）：
- chapters: Chapter[] — 章节列表
- chapterIndex: Map<string, Chapter> — O(1) 查找索引
- 章节状态流转：PENDING -> DRAFT -> PENDING_REVIEW -> REVIEWING -> COMPLETED / DISPUTED
- 流式内容更新：updateChapterContent(id, token) 支持逐 token 追加
- 300ms 节流批量持久化：schedulePersist / flushPersist
- 索引重建确保 O(1) 查找性能

### 3.2 localStorage 持久化

通过 persist.ts 工厂函数实现：
- createStorePersistence<T>(key: string, defaults: T)
- 返回 { load(): T, save(state: T): void, clear(): void }
- 键名隔离：projectStore, beatStore, chapterStore
- 应用启动时读取，状态变更时写入

## 四、Composables 组合式函数

### 4.1 usePhaseWorkflow（核心工作流逻辑）

**位置**：frontend/src/composables/usePhaseWorkflow.ts

复用所有阶段（IDEA / SETTING / OUTLINE / BEATS）的通用工作流逻辑。

**配置参数**：
- projectId, phase, nextPhase — 项目/阶段标识
- getFn, generateFn, confirmFn, rejectFn — API 函数
- generateArgs — 生成参数工厂
- previousPhases — 前置阶段定义（用于状态同步）
- getStatus / getCurrentOutput — 数据提取器

**返回状态**：
- data: T | null — 阶段数据（泛型）
- loading: boolean — 生成中
- regenerating: boolean — 刷新中
- error: string | null — 错误信息
- isConfirmed: boolean — 是否已确认
- initialLoadDone: boolean — 初始加载完成

**核心方法**：
| 方法 | 行为 |
|------|------|
| onMounted | 加载已有数据 + 同步前置阶段状态到 store |
| handleGenerate() | 调用 generateFn -> 更新 data -> 同步 store |
| handleRegenerate() | 调用 generateFn 并传 currentContent 保留用户编辑 |
| handleConfirm() | 调用 confirmFn -> 更新 store -> 路由跳转下一阶段 |
| handleReject() | 重新调用 generateFn -> 替换 data |

**后端状态映射**：
```
后端: PENDING | AI_GENERATING | AWAITING_REVIEW | CONFIRMED | REJECTED
前端: PENDING | IN_PROGRESS (含后两种) | CONFIRMED | REJECTED
```

### 4.2 useAiStatus

管理全局 AI 模型状态：
- aiMeta: AiMeta（modelUsed, degraded, failed）
- isUnavailable: boolean
- setAiMeta() / setUnavailable() / clearAiStatus()
- 全局单例（模块级 ref），跨组件共享

### 4.3 useIdeaParser

解析 AI 输出中的卖点方案为结构化数据：
- 主路径：正则匹配 "## 卖点方案 N:" 格式
- 兜底路径：按 "## " 分块模糊匹配（处理 AI 输出格式偏差）
- 剥离 Markdown bold 标记
- 提取：标题、核心卖点、市场匹配度、爆款参考、差异化分析
- 返回：sellPoints[], hasSummary, oneLiner, fullSummary

### 4.4 useBeatsAdjustment

封装 Beat 调整操作：
- handleAdjustBeat()：AI 调整单章
- handleBatchAdjust()：AI 批量调整（章节范围 + 问题描述）
- handleWordCountUpdate()：字数调整
- handleStructureUpdate()：结构更新（高潮标记等）
- 影响追踪：显示受影响章节和警告信息

### 4.5 useRhythmScore

计算整体节奏评分：
- conflictAvg：平均冲突强度
- varietyIndex：节奏变化度（相邻章节节奏标签变化次数）
- climaxSpacing：高潮章节间距检查
- warnings：预警信息数组

## 六、视图状态机设计

### 6.1 灵感提取 IdeaView
```
INPUT -> SELLPOINTS -> SUMMARY -> CONFIRMED
```
- INPUT：创意输入框 + 示例提示
- SELLPOINTS：3 个卖点方案卡片 + 选择器
- SUMMARY：一句话简介 + 500字简介
- CONFIRMED：只读展示

### 6.2 细纲拆解 BeatsView
```
CONFIG -> GENERATING -> REVIEWING -> CONFIRMED
```
- CONFIG：配置面板（目标章节数 + 字数）
- GENERATING：加载动画
- REVIEWING：Beat 卡片列表 + 统计 + 节奏图 + 调整操作

### 6.3 章节状态流转
```
PENDING -> DRAFT -> PENDING_REVIEW -> REVIEWING -> COMPLETED
                                      |
                                      v
                                   DISPUTED
```

## 七、关键设计决策

1. **Composition API + script setup**：充分利用 Vue 3 的响应式和逻辑复用
2. **Pinia Setup Store**：比 Options Store 更灵活，支持组合式函数
3. **localStorage 持久化**：降低服务端压力，离线可恢复；与服务器数据并存
4. **O(1) 索引查找**：ChapterStore 使用 Map 索引，避免频繁 .find() 扫描
5. **300ms 节流持久化**：流式写入场景下减少存储写入次数
6. **后端状态映射层**：前端 StepStatus 抽象简化后端复杂状态展示
7. **data-testid 覆盖**：每个交互元素均有 data-testid，支持稳定 E2E 测试
8. **泛型 usePhaseWorkflow**：单一 composable 复用 IDEA/SETTING/OUTLINE/BEATS 四阶段共同逻辑
