### Warning（存在隐患）

- **[W1] `input` 字段使用 `(data as any)?.input` 绕过类型检查**：`StepDataResponse` 接口未声明 `input` 字段，组件中使用 `as any` 强制访问。后端 `StepData` 实体确实包含 `input`（Prisma Schema），API 响应中也实际返回该字段——当前仅前端接口声明遗漏。不影响运行时行为，但 IDE 保护和类型安全性有缺口。→ 建议：为 `StepDataResponse` 添加可选 `input?: string | null` 字段。→ 涉及：`api/common.ts`

- **[W2] 测试文件 12 条预存失败与本 Issue 无关**：OutlineView.spec.ts 中存在 12 条先于 #25 已存在的失败测试（集中在 "generate outline flow"、"confirm outline flow"、"error handling" 等 describe 块）。根因：（a）组件无 `data-testid="generate-outline-btn"` 元素——移除了手动生成按钮改为 `watch(initialLoadDone)` 自动生成；（b）旧测试期望 `structure: 'three-act'` 但 #25 前 `selectedStructure` 硬编码为 `'web-novel-ten'`；（c）10ms 等待不足以让 `onMounted` 的异步 prev-phase 同步完成。这些失败不阻塞本 Issue 交付（#25 规格不涉及生成按钮行为），但建议在后续 Issue 中修复以避免 CI 噪音。→ 涉及：`OutlineView.spec.ts`

- **[W3] `cancelSwitchStructure` 在 selector 未触发 change 时被调用会静默成功**：当前 `cancelSwitchStructure` 仅在 `pendingStructure.value` 非空时执行回退。如果用户通过其他方式触发取消（如点击遮罩层关闭 Modal）而 `pendingStructure` 为 null，`selectedStructure` 不会被修改（正确行为），但 Modal 仍会通过 `@cancel` 事件关闭。这是安全行为（NOP），但逻辑意图不够显式。→ 涉及：`OutlineView.vue:258-266`

### Info（优化建议）

- **[I1] `makeOutlineData` helper 未为所有测试共享**：当前 `makeOutlineData` 仅在新 Issue #25 的 describe 块中使用，旧的测试（"initial state"、"generate outline flow" 等）仍使用内联对象字面量。若后续修复预存失败时全面迁移到 helper，可减少 ~200 行重复代码。→ 涉及：`OutlineView.spec.ts`

- **[I2] `parseStructureFromInput` 可提升至 composable**：当前 `parseStructureFromInput` 定义在 `OutlineView.vue` 的 `<script setup>` 内，仅在该组件中使用。若未来 `IdeaView` 或 `BeatsView` 也需要读取 Step 的 `input` 字段（如读取生成参数做回显），建议提升至 `useContentParser` 或新建 `useStepInput` composable。→ 涉及：`OutlineView.vue`

- **[I3] Modal `get-container="false"` 在生产环境中可能产生样式问题**：`get-container="false"` 使 Modal 渲染为 inline 而非 Teleport 到 `document.body`。在测试中这是必要的（确保 `wrapper.find` 可找到 Modal 元素），但在生产环境中可能因 CSS stacking context 导致 z-index 层级冲突（如被其他 `overflow: hidden` 容器裁剪）。当前无已知问题——ErrorModal 组件已在使用相同模式——但若后续出现 Modal 被裁剪或遮罩层不全屏的问题，优先怀疑此配置。→ 涉及：`OutlineView.vue`

- **[I4] `structureOptions` 数组与后端 `VALID_STRUCTURES` 未做编译时同步**：前端 `structureOptions` 定义了三幕式/网文十段/四幕八段三个选项，后端 `step.service.ts` 定义了 `VALID_STRUCTURES` 常量。若后端新增第四种结构（如 `hero-journey`），前端需手动同步。可考虑在 API 响应中返回可用结构列表（如 `GET /structures` 端点）或使用共享常量包。→ 涉及：`OutlineView.vue`、`step.service.ts`
