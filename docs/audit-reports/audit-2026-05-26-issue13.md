### Warning（存在隐患）

- [W1] **ADR-0003 "每维度含四档结论"与实现不一致**: ADR-0003 Decision 1 写道"每维度含四档结论（PASS / PASS_WITH_SUGGESTIONS / NEEDS_REVISION / BLOCKED）"。实际设计中四个维度（POLITICAL_SAFETY / SEXUAL_CONTENT / VIOLENCE / VALUES）各输出 1-10 评分 + issues 数组，四档结论（verdict）是 Review 整体级别的判定，非每个维度独立给出。PRD（第 418 行"每个维度输出 1-10 评分 + 具体违规位置 + 修改建议"）和 CONTEXT.md（ReviewVerdict 条目）均与此一致。ADR-0003 该句为 stale 描述，需修正。
  → 涉及：`docs/adr/0003-tiered-review-and-model-strategy.md`

- [W2] **Issue #13 实现模块归属与 PRD 模块设计不一致**: PRD 模块设计中定义了独立的 `ReviewModule`（接口 `POST /review/evaluate`、`POST /review/appeal`）。Issue #13 将 `evaluateChapter`、`appealReview`、`getAvailableActions`、`forceDisputeChapter` 实现为 StepService 的公开方法，未创建独立 ReviewModule。此为有意的实现选择（避免过早拆分模块），但 CONTEXT.md 将其标注为"StepModule（Review 审核决策 #13）"——命名上混合了 Step 和 Review 两个域概念，可能造成后续模块归属困惑。
  → 涉及：`CONTEXT.md` 实施状态表、PRD 模块设计节

- [W3] **ReviewPanel/AppealModal/DisputeConfirm 组件未接入视图**: 三个前端组件已创建并通过测试（24+17+13=54 条），但未在 WorkflowView.vue 或任何视图中挂载使用，也无对应 API 端点。前端用户在 DRAFTING 流程中尚无法看到审核面板或触发上诉流程。这是实现完整性问题，非文档矛盾——但 CONTEXT.md 标注"已完成 (#13)"容易让读者误认为端到端可用。
  → 涉及：前端 `WorkflowView.vue`、后端 Controller 层
