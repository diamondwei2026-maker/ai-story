# AI 小说创作平台 — 产品需求文档 (PRD)

> **文档角色**：资深产品经理  
> **撰写日期**：2026-06-12  
> **产品定位**：面向网文作者的全流程 AI 辅助创作平台

---

## 一、产品概述

### 1.1 产品定位

一款面向网络小说创作者的 AI 辅助写作平台。与传统写作工具不同，本产品不只是一个编辑器——它覆盖从"一个灵感"到"一部完整作品"的**全创作流程**，在每个关键阶段提供 AI 辅助生成，让作者将精力聚焦于故事创意本身。

### 1.2 目标用户

- **网文新人作者**：有创作意愿但缺乏系统方法论，希望获得结构化的创作引导
- **网文签约作者**：需要高效产出，期望 AI 辅助提升写作速度和内容质量
- **IP 策划/编辑**：为故事项目做前期论证和卖点分析

### 1.3 核心价值主张

1. **全流程覆盖**：从灵感提取到逐章写作，五个阶段一气呵成
2. **结构化创作**：每个阶段都有明确的产出物，避免"写了开头就卡住"的困境
3. **AI 辅助而非替代**：AI 生成内容供作者审阅、修改、确认，最终决策权归作者
4. **内容安全合规**：内置独立审核机制，帮助作者规避平台合规风险

---

## 二、功能全景

### 2.1 创作工作流（五阶段流水线）

```
灵感提取 (IDEA) → 设定集 (SETTING) → 剧情大纲 (OUTLINE) → 细纲拆解 (BEATS) → 正文迭代 (DRAFTING)
```

每个阶段需完成并确认后，方可进入下一阶段。阶段不可跳过，确保创作基础扎实。

### 2.2 项目管理系统

- **项目中心**：多项目管理，展示项目卡片列表
- **项目状态标签**：灵感提取 / 设定集 / 剧情大纲 / 细纲拆解 / 正文迭代 / 已完本 / 已归档
- **快速恢复**：点击项目自动恢复到上次工作进度所在阶段
- **项目归档/恢复**：支持将已完成项目归档，也可从归档中恢复

## 三、阶段功能详述

### 3.1 灵感提取 (IDEA)

**目标**：帮助作者验证故事创意的市场可行性。

**功能流程**：

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 输入创意 | 输入一句话故事创意（可选） | 提供 3 个文案示例引导灵感 |
| 2. 生成卖点 | 点击"开始提取" | AI 基于创意生成 3 个差异化卖点方案 |
| 3. 审核卖点 | 浏览 3 个卖点方案卡片 | 每个方案含：标题、核心卖点、市场匹配度评分(1-10)、爆款参考作品、差异化分析 |
| 4. 反馈重生成 | 输入反馈意见 | AI 根据反馈重新生成卖点方案 |
| 5. 选择卖点 | 从 3 个方案中选择 1 个 | 记录用户选择 |
| 6. 生成简介 | 点击"生成简介" | AI 基于选中卖点生成：一句话简介 + 500字简介 |
| 7. 确认进入设定 | 点击确认 | 阶段状态变为已确认，工作流进入设定集阶段 |

**关键产品规则**：
- 卖点必须包含 4 个维度：核心卖点、市场匹配度、爆款参考、差异化分析
- 简介生成依赖已选中的卖点方案
- 简介内容会被后续 SETTING 阶段引用作为创作基础

### 3.2 设定集 (SETTING)

**目标**：构建故事世界观、角色体系和关系网络。

**功能流程**：

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 触发生成 | 页面加载后自动生成（无需手动触发） | AI 基于 IDEA 阶段的简介 + 用户创意生成完整设定集 |
| 2. 浏览世界观 | 切换"世界观"标签页 | 展示时代背景、地理环境、社会结构、力量体系 4 个维度 |
| 3. 浏览角色 | 切换"角色"标签页 | 展示主角、反派、重要配角，每个角色含名称/欲望/动机/结局 |
| 4. 浏览关系 | 切换"关系"标签页 | 展示冲突关系、情感纽带 |
| 5. 编辑内容 | 点击"编辑"按钮 | 每个维度/角色/关系均可在线编辑并保存 |
| 6. 刷新关联 | 点击"刷新关联内容" | 基于当前设定内容重新生成（含用户修改） |
| 7. 驳回重生成 | 点击"驳回，重新生成" | 完全重新生成设定集 |
| 8. 确认进入大纲 | 点击"确认设定，进入大纲阶段" | 阶段状态变为已确认 |

**产品规则**：
- 设定生成**自动**触发，不需要用户手动操作
- 设定内容被所有后续阶段引用（作为"全局静态上下文"）
- 用户对设定集的修改会被保留并在后续刷新中作为输入

### 3.3 剧情大纲 (OUTLINE)

**目标**：规划故事的宏观结构和叙事节奏。

**功能流程**：

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 选择结构 | 从下拉菜单选择叙事结构模板 | 默认"web-novel-ten"（网文十段结构） |
| 2. 生成大纲 | 点击"生成大纲" | AI 基于设定集 + 所选结构生成完整剧情大纲 |
| 3. 浏览大纲 | 查看按幕/段分组的大纲卡片 | 自动解析模块标题，附带颜色标记 |
| 4. 审核分析 | 查看结构节奏分析、冲突分布、高潮点检测 | 系统自动标注分析注释 |
| 5. 切换结构 | 切换不同叙事结构模板 | 需确认弹窗，确认后重新生成大纲（保留已识别的情节点种子） |
| 6. 驳回重生成 | 点击"驳回并重新生成" | 完全重新生成大纲 |
| 7. 确认进入细纲 | 点击"确认大纲，进入细纲阶段" | 阶段状态变为已确认 |

**支持的叙事结构**：项目当前支持多种结构模板（如 web-novel-ten 网文十段结构），用户可在不同结构间切换并对比效果。

**产品规则**：
- 切换结构时保留关键情节点种子（Key Plot Points），避免完全丢失内容
- 大纲被下一阶段 BEATS 引用拆解
- 结构节奏、冲突分布、高潮点检测为自动审查项

### 3.4 细纲拆解 (BEATS)

**目标**：将大纲拆解为逐章的详细节拍计划。

**功能流程**：

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 配置参数 | 设置目标章节数 & 默认每章字数 | 从项目配置读取默认字数（缺省 3000 字） |
| 2. 开始拆解 | 点击"开始拆解" | AI 基于大纲 + 设定集生成逐章 Beat 计划 |
| 3. 查看节奏图 | 展开"节奏分析"面板 | 展示冲突强度曲线、读者期待值、节奏预警 |
| 4. 浏览 Beat 卡片 | 查看每章的叙事摘要和关键信息 | 每章显示：叙事摘要、冲突描述、字数、节奏标签、钩子因果链 |
| 5. 调整章节 | 调整字数；AI 调整单章；AI 批量调整 | 支持 3 种调整方式 |
| 6. 章节结构 | 标记高潮章节；切换节拍计划 | 动态更新 |
| 7. 节奏评分 | 查看整体节奏评分和预警 | 自动分析 |
| 8. 预览影响 | 查看调整的章节影响范围 | 显示受影响章节和警告信息 |
| 9. 确认进入写作 | 点击"确认细纲，进入正文阶段" | 自动创建对应章节 |

**Beat 计划包含的信息**：
- 叙事摘要：该章节的故事内容
- 冲突描述：核心冲突是什么
- 节奏标签：快/中/慢
- 冲突强度：1-5 级
- 钩子因果链：本章埋下的钩子及预期回收章节
- 高潮标记：是否为剧情高潮章节

**产品规则**：
- 细纲拆解**不会**自动触发，用户必须手动配置参数后点击"开始拆解"
- 超过阈值章节数时自动切换大容量模型
- 调整章节计划会影响关联章节（钩子回收关系），系统会预警

### 3.5 正文迭代 (DRAFTING)

**目标**：逐章生成小说正文，完成最终作品。

**功能流程**：

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 章节列表 | 浏览全部章节卡片（状态、字数、节拍信息） | 自动从 BEATS 阶段创建章节 |
| 2. 生成正文 | 点击"生成正文" | AI 流式生成章节正文 |
| 3. 进入工作区 | 点击章节卡片 | 打开编辑器工作区 |
| 4. 编辑正文 | 在线编辑章节内容 | 实时保存 |
| 5. 重新生成 | 选择模式 + 输入反馈重新生成 | 3 种模式 |
| 6. 提交审核 | 点击"提交审核" | AI 进行四维内容安全审核 |
| 7. 处理审核 | 查看审核结论和修改建议 | 根据结论选择操作 |
| 8. 确认/标记争议 | 确认完成或标记争议 | 修改确认即视为合规自担 |
| 9. 完本操作 | 全部章节完成后点击完本 | 处理待办队列后标记项目完成 |

**三种生成模式**：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 新建续写 | 忽略现有正文，根据节拍计划独立创作整章 | 首次生成 / 不满意全部重写 |
| 段落改写 | 保留剧情骨架，重新组织段落结构和叙事节奏 | 感觉节奏不对需调整 |
| 文笔升级 | 保持剧情和结构不变，仅提升场景描写和文字品质 | 内容 OK 但文字不够好 |

**内容安全审核（四维度）**：

| 审核维度 | 评分范围 | 关注内容 |
|---------|---------|---------|
| 政治安全 | 1-10 分 | 敏感政治隐喻、真实事件影射 |
| 色情尺度 | 1-10 分 | 露骨性描写、低俗内容 |
| 暴力渲染 | 1-10 分 | 血腥残忍描写、美化暴力 |
| 价值观 | 1-10 分 | 负面价值观、歧视性内容 |

**审核结论与操作**：
- **PASS**（≥7 分/维度）：直接通过，章节标记为已完成
- **PASS_WITH_SUGGESTIONS**（5-6 分/维度）：可采纳建议重新审核 / 忽略并确认
- **NEEDS_REVISION**（3-4 分/维度）：可采纳修改重新审核 / 手动修改 / 上诉
- **BLOCKED**（≤2 分/维度）：只能手动修改正文 / 上诉

**上诉机制**：每章节仅限上诉一次，需提交详细理由说明，AI 依据原始审核 + 用户理由重新评估。

## 四、全局产品功能

### 4.1 上下文三层管理

AI 生成正文时自动分层管理上下文信息：

| 上下文层 | 来源 | Token 上限 | 说明 |
|---------|------|-----------|------|
| 全局静态层 | 设定集内容 | 3000 | 世界观、角色、关系等不变信息 |
| 全局动态层 | FactSheet（事实表） | 3000 | 角色状态变化、伏笔进度等动态信息 |
| 局部上下文 | 当前 Beat + 前章摘要 | 2000 | 本章节拍计划和上文摘要 |
| **总计** | — | **8000** | 优先级：局部 > 全局动态 > 全局静态 |

### 4.2 FactSheet（事实表）

- 在写作过程中自动追踪角色状态变化、伏笔铺设与回收
- 章节确认后自动提取变化更新到 FactSheet
- 支持手动查看和同步

### 4.3 变更影响分析

- 用户修改已完成章节正文时，系统自动检测变更类型（无变化/仅空白/小修改/实质性修改）
- 对实质性修改，AI 分析影响范围，标记受影响的后续章节
- 支持"定向修复"：对受影响章节进行针对性修补

### 4.4 模型状态提示

- 当 AI 接口不可用时，弹出提示框告知用户
- 实时显示当前使用的 AI 模型名称
- 支持重试恢复

## 五、产品约束

1. **阶段不可跳过**：必须按 IDEA → SETTING → OUTLINE → BEATS → DRAFTING 顺序
2. **章节顺序生成**：不能跨章节生成正文，第 N 章需等待第 N-1 章完成
3. **上诉仅一次**：每章节内容审核上诉仅一次
4. **切换结构需确认**：大纲切换结构会重新生成内容
5. **完本条件**：所有章节均为已完成或已标记争议状态
